# Development

The toolchain and the development instance — everything needed to work on
the app. What the work serves is [DESIGN.md](../DESIGN.md); how it is
verified is [testing.md](testing.md).

## Tooling

Dependencies live in the Nix flake; work inside it:

```console
$ nix develop
$ composer install          # PHPUnit, Psalm, php-cs-fixer, nextcloud/ocp
$ vendor/bin/phpunit -c tests/phpunit.xml --testsuite unit
$ vendor/bin/psalm --no-cache
$ vendor/bin/php-cs-fixer fix --dry-run --diff
```

The two settings endpoints are OCS, and their contract is `openapi.json`
at the repository root — generated from the controllers' docblocks by the
same extractor the official apps use, committed, and regenerated by the
`openapi` CI leg on every pull request. The same run turns the spec into
TypeScript (`src/types/openapi/openapi.ts`, `openapi-typescript` — the
tables pattern): the admin card imports its `paths`, so the endpoint
strings it PUTs to and the payloads it sends are checked against the
spec by `vue-tsc` — a route that changes in the controller stops the
build, not an admin's save in the browser. The docblocks are the single
source: the `@param` descriptions and the
`DataResponse<Http::STATUS_…, array{…}>` unions feed Psalm, the spec and
the card's types, so a change to any of them without regenerating fails
the leg.

```console
$ composer bin openapi-extractor install   # once per tree; fresh CI
                                           # installs get it through the
                                           # scoping hook's bin-all pass
$ composer run openapi                     # openapi.json + the TS types
```

The extractor lives in its own composer bin namespace
(`vendor-bin/openapi-extractor`, the pattern `vendor-bin/php-scoper`
already set) so it never mixes with the app's dependencies; only its
`composer.json` is committed, the lock is not — the leg regenerates from
the constraint and fails loudly if the output drifts. The leg knows
about the generated types on its own: the workflow template checks for
`src/types/openapi/openapi*.ts` and sets up node when the file exists,
so nothing is left to wire.

The admin card is Vue and TypeScript behind Vite (`src/`, the shape the
Nextcloud app template sets): `npm run build` writes `js/fts_sql-admin.mjs`
and the CSS into `js/` and `css/`, emptying both directories first, and
nothing built is committed — `make build` and `make appstore` run the build
themselves.

```console
$ npm ci && npm run build   # the admin card into js/ and css/
$ npm run lint              # eslint, the unified Nextcloud config
$ npm run stylelint         # stylelint over the components' styles
$ npm run typecheck         # vue-tsc over src/ and vite.config.ts
```

The shell ships PHP 8.2 — the manifest floor — with `intl` deliberately
removed (nothing may depend on it) and SQLite with FTS5 for experiments.

## Development instance

The instance runs on [nextcloud-docker-dev][docker-dev] (checkout outside
this repository), one Nextcloud 34 on PostgreSQL 16, with this repository
bind-mounted as `apps-extra/fts_sql`:

```console
$ cd /path/to/nextcloud-docker-dev
$ docker compose up -d stable34
$ ./scripts/occ.sh stable34 -- app:enable fts_sql     # runs pending migrations + the artefact repair step
$ ./scripts/occ.sh stable34 -- db:schema:export       # inspect the tables
```

Select the platform for the framework and run it end to end:

```console
$ ./scripts/occ.sh stable34 -- config:app:set fulltextsearch search_platform \
    --value 'OCA\FtsSql\Platform\SqlPlatform'
$ ./scripts/occ.sh stable34 -- fulltextsearch:index -r
$ ./scripts/occ.sh stable34 -- fulltextsearch:search <user> <needle>
$ ./scripts/occ.sh stable34 -- fulltextsearch:test   # the framework's own smoke test
```

After changing the `language` setting or a failed run, the remedy is always
`fulltextsearch:reset` (it asks for confirmation) followed by another index.

`fulltextsearch` and `files_fulltextsearch` (stable34 branches) sit next to it
in `apps-extra/`. The engine-specific overlay — PostgreSQL 16 instead of
`postgres:latest`, the bind mount — lives in the untracked
`docker-compose.override.yml`.

The web frontend answers at `http://stable34.local` (add it to `/etc/hosts`,
or curl with `-H 'Host: stable34.local'` against the proxy port).

[docker-dev]: https://github.com/nextcloud/nextcloud-docker-dev
